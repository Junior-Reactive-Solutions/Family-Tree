# Bintukwanga Family Tree

A private, interactive family tree for the descendants of Antiel Bintukwanga and Maria Christine Nakayima: five generations across nine branches. Relatives enter a family access code, then browse the tree, read each branch as a list, open profiles, and send corrections through a suggestion-only chatbot. Admins review suggestions and fix records.

Live site: https://family-tree-sepia-nine.vercel.app (access code required)

## Privacy

The tree names living people, including children, and the repository is public. Family data is therefore **never committed**:

- `data/`, the source plan (`bintukwanga-family-tree-plan.md`) and `apps/web/public/tree.snapshot.json` are gitignored.
- The live site serves the data only from the API, and only to visitors who have entered the family access code.
- Pages carry `noindex` and `robots.txt` asks search engines to stay out. Only link-preview bots may read the home page and share image, which contain no family data.

## Local setup

Requirements: Node 22 (see `.node-version`), pnpm 10.

```bash
pnpm install
```

### 1. Environment

Create `apps/api/.env` (never commit it):

```bash
DATABASE_URL=postgresql://...        # Neon connection string (pooled)
FAMILY_ACCESS_CODE=some-long-code    # leave empty locally to skip the access screen
SESSION_SECRET=any-long-random-string
IP_HASH_SALT=any-random-string
CORS_ORIGINS=http://localhost:9901
PORT=9902
```

Create `apps/web/.env.local`:

```bash
VITE_API_URL=http://localhost:9902
```

`.env.example` at the repo root lists every variable.

### 2. Family data

Put the source plan file in the repo root, then generate the seed:

```bash
pnpm seed:build
```

This parses Section 6 of the plan into `data/family.seed.json` (285 people, 59 unions, 226 parent links) and a local snapshot for the web app.

### 3. Database

```bash
pnpm --filter @family-tree/api db:migrate    # apply migrations in db/migrations
pnpm --filter @family-tree/api seed:db       # upsert the seed into Postgres (safe to re-run)
```

Without `DATABASE_URL` the API serves the seed file read-only, and the admin area is disabled.

### 4. Run

Local ports use the 9900 range to avoid clashing with other projects.

```bash
pnpm --filter @family-tree/api dev    # API on http://localhost:9902
pnpm --filter @family-tree/web dev    # web on http://localhost:9901
```

### 5. Admin account

```bash
pnpm --filter @family-tree/api admin:create you@example.com "a-long-unique-password"
```

Passwords need 12 or more characters and are stored as argon2id hashes. Running the command again for the same email changes the password and signs out that admin's existing sessions. Sign in at `/admin`.

## Deployment

Every merge to `main` deploys automatically: Vercel rebuilds the web app and Render rebuilds the API.

### Web (Vercel)

- Project root directory: `apps/web`, framework preset Vite. The monorepo installs from the repo root.
- No environment variables are needed in production. The app calls `/api/...` on its own domain and `vercel.json` rewrites those requests to Render, so login cookies stay same-origin.
- `vercel.json` also sets the Content-Security-Policy and other security headers.
- If the Render URL changes, update the `/api/:path*` rewrite in `vercel.json`.

### API (Render)

Configured as a Node web service (`render.yaml` documents the settings):

- Build: `pnpm install --frozen-lockfile --prod=false`
- Start: `pnpm --filter @family-tree/api start`
- Health check: `/api/health`

Environment variables on Render:

| Variable | Purpose |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | Neon pooled connection string |
| `FAMILY_ACCESS_CODE` | The code relatives enter. Required: production refuses to serve family data without it |
| `SESSION_SECRET` | Signs admin and access cookies. Changing it signs everyone out |
| `IP_HASH_SALT` | Salt for the hashed IP stored with suggestions (raw IPs are never stored) |
| `CORS_ORIGINS` | Comma-separated allowed origins, e.g. the Vercel URL and `http://localhost:9901` |
| `TRUST_PROXY` | `2` (Vercel, then Render) |

The free plan sleeps after about 15 minutes without traffic. The first visit afterwards can take up to a minute; the site shows a short note while it wakes, and later visits are fast.

### Database (Neon)

Run migrations against production from your machine with the production `DATABASE_URL` in `apps/api/.env`:

```bash
pnpm --filter @family-tree/api db:migrate
```

## Operations

- **Change the access code:** edit `FAMILY_ACCESS_CODE` on Render (it redeploys). Devices that already entered the old code stay unlocked until their 30-day cookie expires; also change `SESSION_SECRET` to sign everyone out immediately.
- **Lockouts:** 8 wrong codes from one visitor locks that visitor out for 15 minutes. Correct codes never count.
- **Admin password:** re-run `admin:create` with the same email.
- **Review queue:** people with inferred genders or open questions appear under Admin, Review queue.

## Security

- Every text box is validated with the shared zod schemas on the server, length-limited, Unicode-normalised, and stripped of control and invisible characters. User text is always rendered as plain text.
- Rate limits per visitor plus hard caps keyed on Cloudflare's `cf-connecting-ip` (see `apps/api/src/limits.ts` for why forwarded headers are not trusted).
- Admin: argon2id, httpOnly SameSite=Strict session cookie, CSRF header on changes, sessions tied to the current password.
- CI runs typecheck, tests and `pnpm audit`; CodeQL scans every PR; Dependabot keeps dependencies current.
- To report a vulnerability, see `/.well-known/security.txt` or open a private advisory on GitHub.
